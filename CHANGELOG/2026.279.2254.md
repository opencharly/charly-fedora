# 2026.279.2254 — fix(install-test): stop asserting the retired /etc/charly/charly.yml

## Summary

`build.yml`'s **Install-test** asserted the packaged system config `/etc/charly/charly.yml` exists — but the package **intentionally no longer ships it**, so building this repo from a post-drop charly fails at Install-test:

```
$ test -f /etc/charly/charly.yml || { echo "/etc/charly/charly.yml missing"; exit 1; }
/etc/charly/charly.yml missing
```

Measured on `charly-arch` run [37540936276](https://github.com/opencharly/charly-arch/actions/runs/37540936276) (packaging charly `2026.279.2144`). This repo carries the identical assertion.

**Root cause — a stale test (R5 class).** `spec#183` deleted `#PackagingConfig`; `sdk#313` (2026-09-27) dropped the render (`packagekit/nfpm_config.go`: *"The former system-wide config emission (`/etc/charly/charly.yml`) is DROPPED"*). charly's own `packaging/charly.yml` says: *"The package intentionally does NOT ship /etc/charly/charly.yml … stays a READ location only."* The last successful build of each packaging repo predates the drop, so the assertion was latent until the next release to package.

**Change:**
- assert the retired config is **absent** (`test ! -e /etc/charly/charly.yml`), so a regression that re-adds it fails loudly;
- run `charly mcp serve` from `/tmp` (no packaged project dir exists to `cd` into);
- drop the `charly box validate -C /etc/charly` step (no packaged project).

Refs opencharly/charly-arch#11 — the cross-repo tracker; `charly-arch`'s leg is merged (#12), this is one of the remaining three.

## How tested

Built a **real** package with the released `generate-packages` plugin against the current `packaging:` config, then ran the corrected assertions in an `archlinux:latest` container (the same package shape every distro leg installs):

```
$ bsdtar -tf charly-2026.279.2144-1-x86_64.pkg.tar.zst | grep etc/
(no /etc entry — confirms the intentional drop)

# in the container, after installing the package:
OK units present
OK WantedBy present
OK no enable marker
OK config correctly absent (retired)
```

The `charly mcp serve` assertion was proven against the real binary: with no project dir it stays up until the timeout (`exit 124`):

```
$ (cd /tmp && timeout 5 charly mcp serve --listen 127.0.0.1:18765); echo $?
charly mcp: serving 93 tools on http://127.0.0.1:18765/mcp
124
```

The YAML parses (`python3 -c "import yaml; yaml.safe_load(...)"` → OK). The per-format install (dpkg/rpm/apt) is exercised by this repo's `build.yml` Install-test at dispatch.
